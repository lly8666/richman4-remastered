## 独立 MOD 规则

| 项目 | 原版 `main` | 本 MOD |
| --- | --- | --- |
| 股票报价上限 | 9,999 | **999,999** |
| 每类道具持有数量 | 9 | **999**（独立 16-bit 内存及 MOD 存档） |
| 每种卡片持有数量 | 原版卡片 15 格，每张占一格 | **每种 999、重复卡片堆叠**；保留最多 15 种不同卡片的快捷格，库存/商店/夺取视图在卡片下沿用金边徽标展示 ×2..×999 |
| 新游戏总初始资金选项 | 10,000 至 300,000 共六档 | 全部保留，增加 **30,000,000**、**900,000,000**，共八档 |
| 新开局默认档 | 200,000 | 仍为 **200,000**，避免意外改动 |
| 物价指数 | 随财富提升 | **固定 1**；真实 DAT 读入也归一 |
| 市场流通股票/供股数量 | 原始配置 | **原配置 × 10,000**，单股最多 **100,000,000 股** |
| 每股最高持仓 | 旧 32-bit 计算限制 | MOD 运行时安全上限 **1,000,000,000 股** |
| 股票交易余额、成本、总资产 | 32-bit 范围/原版算术 | **signed 64-bit**，中间计算检查溢出；不把超过 2,147,483,647 的资产截为该数 |

注意：交易的份额窗口和输入事件仍使用 32-bit *单笔数量*，但 1 亿份流通总额远低于 INT32_MAX，可正常输入。股价是二进制 float，与原版相同；显示/结算仍按原版小数价位规则，不是货币最小单位的十进制定点数。

### 为什么必须用 64-bit

极端情况下，每股 999,999 元 × 100,000,000 股 = **99,999,900,000,000 元**（近 100 万亿元）；同一玩家 12 只股票的总资产可能上万万亿元量级。32-bit 有符号最大仅 2,147,483,647，旧代码会出现负余额、持股回绕、错误的财富比较。MOD 把 PlayerState 的 `cash`、`bank_balance`、`loan`、`special_finance`、持仓 `StockHolding.amount`、`World.public_fund`、`stocks::PurchaseResult.cost`、`stocks::SaleResult.proceeds`、`stocks::player_wealth`、事件金额等拓宽为 64-bit；市售股数和每日配额拓宽到 32-bit 无符号。

交易路径必须先检查配额、银行余款、每人持仓、最终加减范围和计算后的平均成本，验证完毕才写入任何余额；非法超限交易应完整拒绝，不得发生部分成交。AI 在大额市场启用 64-bit 预算路径，避免原版 32-bit 预算溢出。

**边界说明：** 企业账面资金 `Commercial.funds/funds_change`、点券、部分新闻/魔法/拍卖规则和玩家财务指标仍保留历史字段/接口；并非整个引擎所有可能涉及金钱的项目都已无条件拓宽至 64-bit。当前仅可确认经过专门检查的 MOD 股票主交易、玩家余额与净资产，以及存档扩展。极端新闻、股息、银行或企业环节仍需进一步专项测试，不应将 CI 通过当成“永远不会有 bug”。

**64 位拍卖结算专项：** 玩家现金、卖家银行余额、公共资金池在土地/设施拍卖时使用受检 64 位算术；变更所有权前同时预检买家与收款方余额，越界拒绝并保持拍卖可重试。新增超过 `INT32_MAX` 的公拍、转卖和接近 `INT64_MAX` 的拒绝原子性回归测试。拍卖报价/单次加价仍保留原版 32 位范围，累计消费/收入计数仍按旧字段保存。其他新闻、企业、月结及跨文件存档风险不因此视为已验收。

**魔法屋高额资金专项：** 按总资产、现金、银行存款选择魔法对象时使用完整 64 位比较；“现金全存银行”改为受检 64 位加法，并在多目标施法前预检全部账户，避免溢出时前几名玩家已经被部分转账。新增万亿级排序、资金守恒与 `INT64_MAX` 多人原子拒绝测试。其他魔法效果以及 16 位点券沿用各自既定边界，仍需独立审计。

**MOD 卡片商店补货与防丢档：** 和道具一样，正常 MOD 游戏进店时的 15 张卡片货架在原公共卡片供给耗尽后仍可从全部 30 种类型补货；买入已空的公共供给不把 0 回绕成 255，单种累计至 999 拒绝再买。新保存的 DAT 末尾添加不改变任何原始字段偏移的 `RICH4-MOD-COMPANION-REQUIRED-3` 哨兵，若用户只复制 DAT 而遗漏 `.DAT.mod`，Android 载入会明确拒绝，防止将 999 张误当 1 张。旧 MOD DAT 没有该标记的无法追溯缺失附档，务必整组备份；第三方原版 Windows 程序是否接受附加尾部尚未验收。

**银行贷款与股票持有跨存档专项：** 增加真实银行 8 亿贷款、999999 元报价买入 1000 股、DAT + ECON-3 校验侧车重新读取后的完整资产守恒测试；并增加玩家间 30 亿存款、5 亿股高额持仓及接近 `INT64_MAX` 拒绝原子性测试。负净值有时是股价亏损，但未经余额/贷款/行情三方核对，不应把异常显示一概归类成正常亏损。

**卡片堆叠与存档：** MOD 在运行时将旧 15 格重复卡片合并为各自一格，单种上限 999；使用、出售、抢夺及商店买入均按一张扣减，批量售卡按真实张数计价。原版 DAT 继续只写每种卡的单个 ID 预览，真实 30 种卡片数量写入校验绑定的 `RICH4-MOD-ECON-3` 侧车，读取仍兼容旧 `RICH4-MOD-ECON-2` 与 `RICH4-MOD-TOOLS-1`。大额堆叠保存**必须一起保留 .DAT.mod**；缺附档的低数值 DAT 可读，高额卡片仅靠 DAT 无法无损还原。渲染已加入金边深色数量标识，但 Android 构建与真机视觉验收仍待完成。

**商店补货与借贷专项：** 商店的八类道具不再因为原版共用供给字节耗尽而从货架消失；每次进店可购买、每类最多 999，供给已为零时不再将库存减成 255。玩家间交易的道具接收上限同步由旧 9 更新到 999。人类贷款在修改余额前预检两项 64 位金额，AI 贷款额度与还款判断不再将总资产/负债通过 32 位乘法窄化。借款同时增加存款和负债，因而正常借款当刻**不会使净资产增加或变负**；股票下跌仍会使净资产减少。

## 存档：保留原版 DAT + MOD 附属文件

原版 Windows `Save?.DAT` 的道具数量只有 8 bit、股市供应/配额 16 bit、玩家现金/存款/持仓 32 bit。不能把这些字段直接扩成 64 bit，否则整个旧格式偏移将失效。

MOD 保留原始 DAT 字节布局；溢出旧字段范围的数据在 DAT 写入**饱和的兼容预览**（上限分别为 255、65,535、2,147,483,647），同时将**真实数值**写进同名 `.DAT.mod`，格式标志 **`RICH4-MOD-ECON-2`**，保存：

- 对每位玩家：15 种道具数量、现金、存款、贷款、特殊融资额和 12 支股票持股数；
- 每支股票：实际剩余份额及当天交易配额；
- 各个企业的未售原始股数、公共资金池；
- 原 DAT 字节数、FNV-1a 64-bit 校验值，以及玩家/股票/企业数量。

读档会核对附属文件和 DAT 是否对应，并且**先完全验证再一次性恢复**。继续支持旧的仅保存工具数量的 `RICH4-MOD-TOOLS-1` 附档。没有附档的原版 DAT 可以正常读；有明显高配额/高背包数量但缺少附档时拒绝读取，避免悄悄丢失数值。

**备份时请将 `.DAT`、`.DAT.mod`、`.rng` 一起复制；不要只复制主 DAT。** 使用 MOD 后的高金额存档不能依靠原版 Windows 程序完整还原。
