# MOD 原版事件/动画播放顺序审计 · 2026-10-17

## 方法与边界

依据 `docs/ui/effects.md`、`docs/ui/messages.md` 中已复核的原版 EXE/汇编路径，
再追踪 `src/game.cpp`、`tools/native_game.cpp`、
`tools/screens/{effects,messages,items,monthly}.cpp` 的顺序。
动画在核心引擎里 **提前结算规则数值** 是原版惯例：数据更改不代表应提前显示结果。
正确的视觉链路是先显示 **前景提示／动画**，再显示 **结果文字／气泡**；
非动画的日常数值通知按现有游戏逻辑执行。

## 按事件链路逐项检查

| 类别 | 原版对应链路 | 当前 MOD 视觉顺序 | 证据与限制 |
|---|---|---|---|
| 行走/骰子 | 数值预先掷出 → 骰子 FLC → 一步步行走 → 落点暂停 | 保留骰子数值事先决定但不先显示落点结果；走完、等待 5 tick 后落点处理 | `dice_roll` 与 `MainScreen`，原版 values-before-movie，不应该机械后移 |
| 买地/升级/施工 | 先选择/付款，执行规则 → 以旧建筑为底图播升建/塌毁影片 → 提交帧显示新建筑 | `EffectEvent.previous_owner/level/type` 和 `after_events` 在主板/EffectPlayer 同步恢复旧外观 | 已有建造、五层特效与购买回归；真机帧边缘仍待实测 |
| 过路费/商城/旅馆 | 收费原因/金额弹框 → 人物说话/支付 → 结算 | `Announcement::toll` 在 `rent_paid` 前，嫁祸卡在提示后选目标 | `tests/game_tests.cpp` 顺序断言；银行存款会先于现金耗用 |
| 主动卡/被动卡 | 展示卡片图片 → 投掷/拆除/魔法等 → 目标的反馈文字 | **本轮关键修复：** `items_.observe` 从整批事件入队阶段移到各事件**真正播放**时；卡片 popup 被纳入阻塞队列，后面的消息音频/结果不得提前启动 | 之前 `items_.observe` 遍历未来整批事件并立即排卡片图，导致尚未播放动画就露出最终卡片状态 |
| 导弹/核弹/地雷/爆炸 | 投射/爆炸影片 → 医院车/结算反馈 | 影片 `EffectKind` 顺序保留，在结果事件之前；保留旧人物/建筑到电影提交帧 | `tests/game_tests.cpp`、`effects.md` §4 已有顺序验证 |
| 住院/入狱/消失/回来 | 入场语气球 → 救护/警车/UFO/飞机电影 → 住院/坐牢反馈 | 旧人物坐标通过 PendingActor 保留到影片的相应提交帧，反馈通知排在电影之后 | `add_confinement/disappear`，需真机测人物姿势和相机切换 |
| 神明附身/离开 | 恶神声前置、入场 FLC → 2400ms 神明字幕 → 卡片奖励/损失 → 转轮（适用） | 入口电影与字幕顺序维持，先展示字幕再转轮/后续结果 | 现有 God 种类 1–15 回归，附身 sprite 在预告期间隐藏 |
| 新闻/命运 | 公告屏 → 新闻针对地块电影/事件反馈 → 目标选择/结算 | `screen_first` 把公告置于处理器的效果之前；遇到嫁祸选择先展示触发预告，然后只对最终结算跑一次回放 | 被动卡首个选择可能需要重复决策；`NeedChoice` 通过 checkpoint 复放，不得重复扣钱 |
| 设施轮盘/神明老虎机 | 滚动/停止电影 → 结算金额/反应 | `SpinnerState` 与 `EffectKind::roulette/money_spinner` 先于对应结果反馈 | 原版值事先确定，不能提前弹中奖金额 |
| 月中企业分红 | 完整分红表/高额金额 → 账本提示 | 原先分红本身已是 presentation effect，结果延后 | `DividendRow` 64 位，企业股东预先验算但动画按队列 |
| **每月 15 日乐透** | 主持人／彩球抽奖影片 → 中奖球号／得主揭晓 | **已修：** `lottery_draw` 影片现在排在“彩票开奖：N”最终通知之前 | 核心 CI 日期为 14→15，不能用 31→次月来测乐透 |
| **月底结算** | 月结画面/银行存款收益表 → 本月结算完成 | **已修：** `month_report` 在“月结完成”通知之前 | 31→次月的单独测试 |
| **破产** | 音乐2 → Data[555] 破产影片 → 2s 停留 → 破产话语/胜负 | **已修：** 先把 `bankrupt` 效果排入队列，再推 `player_bankrupt` 结果；游戏结束结论更晚 | 对照 `docs/ui/messages.md` §3.5，核心测试断言 `after_events` |
| 拍卖成交 | 出价选择 → 售出画面/木槌 → 赢家结果 | `AuctionRoom.start_sold` 在成交事件真正展示时触发，队列等待售出效果结束 | 视觉模式真实滑动/触摸尚未全面验收 |
| 魔法屋/道具购买 | 施法框/动画 → 魔法结果/变化；商店先看货再确认 | `items_.magic_cast_active` 单独阻塞视觉队列；货架/库存卡片 popup 修复提前出现 | UI 动画本身还需 Android 实机验收 |
| 年节/胜利、特殊角色 | 节庆烟火在日期通知前；胜利/视频及部分特殊人物行为依照原版研究 | 已保留原基准 FLC 表与暂停；**部分原版胜利 AVI、特殊 NPC 对应影片的精确帧点尚未从汇编完全验证** | `docs/ui/messages.md` 标记的 UNVERIFIED 不声称已解决 |

## 队列不变式与新增测试

1. `EffectEvent.after_events` 指向同批次里电影应插在第几个 `GameEvent` 之前；
   `native_game.cpp::observe` 逐一合并，不得改变到达顺序。
2. `GameSession::run_rule` 需要回答（`NeedChoice`）时重放规则并删除已播放段，不得重复动画、
   扣卡、扣款或 RNG；新闻/命运说明与决策先于真实结果。
3. 电影和卡片图片播放期间禁止 core tick、下一个 popup、结果文字及音频；
   已将原来在 `observe` 遍历**所有未来结果事件**就调用 `items_.observe` 的错误移到
   `present`，并让卡片图片成为 `presenting()` 的阻塞条件。
4. `tests/game_tests.cpp::mod_ordered_original_result_movies` 模拟了破产影片、15 日乐透
   和月底结算电影与结果文字顺序；原有导弹/医院、过路费、神明入场、卡片嫁祸测试继续保留。
   Core GitHub CI 有效，**仅 Android 完整构建与手机实测能检查 640×480 合成、帧率、音频、滑屏**。

## 仍需后续实机确认

- 原版 Windows 的逐帧视觉/声音时间、会话队列在长时间 autoplay 期间的顺序；
  现有单元回归只验证节点和电影播放顺序，不能验证所有特殊角色组合。
- 破产后拍卖、神明损毁双电影、多玩家连续新闻+卡片、节假日叠加月底报表，
  长组合需实际场景录像或新的确定性截图对照。
- APK 使用持久签名需要用户自行配置 GitHub Secrets；签名配置与动画修复**互相独立**。
