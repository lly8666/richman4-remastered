# 動畫播放先後順序審查（2026-10-15）

範圍：截至本次修復的 `EffectKind` 全枚舉、`GameSession::effect/emit`、
`Application::observe/pump_presentation` 和 `EffectPlayer::draw`。原版依據
`docs/ui/effects.md` 記錄的反組譯函式、原遊戲素材索引與動畫提交幀（**沒有聲稱對每一種
動畫做過原始 EXE 逐幀影片對照**）。

## 確認並修正的時序錯誤

- **飛彈 / 核子飛彈**：`tool_callbacks().blast` 舊順序為
  `area_damage`（會排入住院、救護車等結算）→ `effect(missile)`。
  因 `observe()` 按事件時間戳與效果佇列合併，導致玩家先看到結算，後看到爆炸。
- 修正為排入 FLC 電影效果 → 同步計算範圍傷害 → 後續結算事件。
  原版同樣先把規則狀態變更，再播放動畫；重構版仍在一次規則操作中計算結果，
  但在顯示上先播放飛彈，且 `EffectPlayer` 到第 **9** 幀才從舊地圖切到受損的新地圖。
- 測試 `missile_presentation_order` 對道具 7/13 斷言：飛彈/核彈
  排在救護車動畫與住院提示前，並保持最終住院狀態。

## 仍非完整復刻（不要混同為整條時序有誤）

1. `fcn_00451985` 的**地塊亮暗脈衝**（天使、惡魔、換地、換屋及部分新聞）尚未完整實作。
2. 核彈的 `flags 0x80090001` **白化/閃白**顯示與某些受損建築的同幀切換仍需視覺驗收。
3. 多個效果在同一核心 tick 連續修改地圖時，`snapshot_` 只能保留一張此前的
   Scene；原版每個提交幀各自重畫，複合效果可能在非首個提交幀顯示過早/過晚。
4. `RICH4.CFG[1]` 原版僅跳過指定類別 FLC，移植版的「動畫過程」主要控制
   互動小遊戲；選項開關對每一類特效的區分尚不完全。
5. **語音和音效**各別效果的起播幀、Win32 中間停頓、被跳過後的恢復動作，
   沒有原始 EXE 全類型逐幀測試佐證，不宜宣稱全部一致。
